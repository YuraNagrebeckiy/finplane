## 4. Что изменено

**Сервер (`Code.gs`):** клиент передаёт `clientId`, `baseRev` (версия сервера, с которой сверялся) и `changes` (что изменил сам). Если клиент «отстаёт», сервер применяет только его правки к актуальным данным (слияние по ID: свои добавления, правки и удаления; чужие записи не трогает). Продолжение цепочки одного устройства — по-прежнему простая замена. Устаревшие клиенты (без `baseRev`) работают как раньше. Быстрый `?ts=1` (читает 1 строку), причина последней ошибки без stack trace видна приложению, ручная правка в Таблице помечается как «sheet», проверка `investedRemainder` допускает не расписанные по статьям инвестиции (остальные проверки строгие), при импорте из листа этот остаток сохраняется.

**Клиент (`index.html`):** версия сервера отслеживается отдельно от часов; неотправленное хранится на устройстве и не затирается загрузкой; новое устройство сначала загружает данные семьи; опрос раз в 25 с; повтор безопасен (отправляются изменения, а не слепок); при отказе сервера показывается этап/причина/ID и повторы прекращаются до следующего действия; ссылка «🔗 Ссылка для другого устройства» (адрес скрипта в части после `#`, на GitHub не попадает) — для настройки остальных устройств без вставки URL в публичный файл.

## 5а. Данные из вашей проверки `?ts=1` (09.11)

Ответ `{"updatedAt":1793833437601,"clientUpdatedAt":0,"lastClientId":"","merged":false}` означает:
- новая версия сервера развёрнута (поля `lastClientId`/`merged` есть только в ней);
- последняя запись в Таблицу — **5 ноября 2026, 01:03 (Калининград)**, сделана старой версией скрипта: метки `clientUpdatedAt` в ней нет;
- за 5 дней после этого не записано ничего, то есть свежие данные могут лежать только в браузерах устройств.

Поэтому при первом запуске нового приложения на устройстве со своими данными приложение **не решает само**, чья версия основная, а спрашивает: «Загрузить данные из Таблицы» (данные устройства заменяются) или «считать данные этого устройства основными» (заменяются данные Таблицы). Отказ от обоих вариантов ничего не меняет, вопрос повторится при следующем запуске. В вопросе указана дата данных Таблицы. Пустая Таблица заполняется без вопросов.

**Порядок для вас:** сначала скачайте CSV на каждом устройстве (вкладка «Google Таблица»), затем откройте новое приложение на устройстве со **самыми свежими** данными и выберите «основные данные этого устройства». На остальных устройствах выбирайте «загрузить из Таблицы».

## 6. Ограничения (честно)

- Если два устройства одновременно правят **одну и ту же** запись, остаётся последняя пришедшая.
- Сводка/прогноз/«Где были» в Таблице обновляются после слияния повторной отправкой, а не мгновенно.
- Закрытая вкладка или телефон в фоне не опрашивают сервер; при возвращении проверка идёт сразу (в тесте — за секунды).
- Защиты доступа по-прежнему нет: ссылка Web App = пароль, и GET отдаёт всё состояние. Я это **не менял** (нужно ваше решение, см. п. 8).
- Подтверждение записи по-прежнему через `no-cors` + проверочный GET (как было): механизм не менялся.

## 7. Как внедрять (по шагам, с минимальным риском)

1. **Копия Таблицы:** Файл → Создать копию. Работаем сначала на ней.
2. На копии: Расширения → Apps Script. Оставьте **один** файл `Code.gs`, вставьте новый `Code.gs` целиком, удалите старые файлы модулей. Сохраните.
3. Развернуть → **Управление развёртываниями** → карандаш у существующего → **Версия: Новая версия** → Развернуть (так адрес `/exec` не изменится). Доступ: «Выполнять от: меня», «Доступ: все». Один раз подтвердите разрешения (Таблицы, Календарь).
4. Откройте `АДРЕС/exec?ts=1` — должен вернуться JSON с `updatedAt`, `clientUpdatedAt`, `lastClientId`, `merged`.
5. Подключите **тестовую страницу** (новый `index.html` где-нибудь отдельно, например `test.html` в репозитории) к копии. Проверьте на двух устройствах: добавить расход → через ≤30 с виден на втором; одновременно добавить по расходу на каждом → остались оба; удалить цель → исчезла на втором.
6. После успеха: замените `Code.gs` в рабочем проекте тем же способом (новая версия того же развёртывания) и заменить в репозитории `index.html`, `Code.gs`, `AppsScript_Complete.gs`. Тесты положить в `tests/`.
7. На каждом устройстве один раз откройте приложение: оно само отправит/сверит данные. Остальные устройства настраивать кнопкой «🔗 Ссылка для другого устройства».
8. Если что-то пошло не так — лист `_Журнал ошибок синхронизации` (этап, ID, stack trace) и откат: «Управление развёртываниями» → прежняя версия.

Запуск тестов: `node tests/sync-protocol.cjs` и `node tests/sync-e2e.cjs` (из корня репозитория); старые: `node tests/finance-regression.cjs Code.gs Code.gs`.
