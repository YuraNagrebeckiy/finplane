# Finplane — установка Google Apps Script

Дата сборки: 05.11.2026
Файл полного кода: [AppsScript_Complete.gs](./AppsScript_Complete.gs)

## Что находится в комплекте

В `AppsScript_Complete.gs` объединены пять актуальных файлов ветки `main`:
- `Code.gs` — веб-приложение, загрузка и запись состояния, календарь;
- `BudgetIdentity.gs` — постоянные ID операций и статей бюджета;
- `BudgetSheet.gs` — безопасный экспорт/импорт бюджета;
- `FinplaneSafety.gs` — проверки данных, транзакционное восстановление, триггеры;
- `MarketData.gs` — рыночные показатели и автоматическое обновление.

## Важно до установки

Это подготовленный комплект для ручной установки, а не подтверждённый production-релиз. Не вставляйте его в рабочий Apps Script, пока не проверите его на копии Google Таблицы.

В текущей версии остаются два блокера:
1. Веб-приложение не проверяет подлинность входящих POST-запросов. Настройка доступа «Все» означает, что URL веб-приложения фактически является публичной точкой записи. Не публикуйте URL и не храните его в открытом репозитории.
2. Защита конфликтов между устройствами пока основана на временных метках. Полноценный протокол с базовой ревизией и подтверждённой клиентской записью ещё не внедрён. Поэтому нельзя считать безопасным одновременное редактирование с двух устройств.

Дополнительно нужен интеграционный тест на копии таблицы: старые данные, бюджетные ID, долги без целей, календарный триггер, рыночные показатели и мобильный браузер.

## Порядок установки, когда тесты будут завершены

1. Откройте именно копию Google Таблицы, а не оригинал.
2. В этой таблице выберите **Расширения → Apps Script**.
3. Откройте `AppsScript_Complete.gs` и скопируйте весь текст целиком.
4. В редакторе Apps Script оставьте один файл `Code.gs`. Замените его содержимое полным текстом из комплекта.
5. Удалите старые отдельные файлы `BudgetIdentity.gs`, `BudgetSheet.gs`, `FinplaneSafety.gs` и `MarketData.gs`, если они уже есть в этом Apps Script-проекте. Иначе появятся повторные объявления функций.
6. Сохраните проект.
7. Выберите функцию `authorize` и выполните её вручную. Разрешения выдавайте только проекту, которому доверяете. Она создаёт/проверяет календарь, лист рыночных данных и триггеры.
8. Проведите проверку на копии таблицы: отправка тестовой цели, загрузка состояния, одна тестовая бюджетная операция, ручная правка цели, проверка календаря и статуса синхронизации.
9. Только после успешных тестов создайте новую версию веб-приложения и обновите URL в приложении, если URL изменился.

## Что не делать

- Не запускайте `resetToDefaultData` на рабочем приложении: это эталонные данные, а не восстановление вашей семьи.
- Не удаляйте листы `_Состояние`, `Статистика Бюджета`, `Цели` и `Рыночные данные` вручную.
- Не включайте публичный доступ и не переносите URL веб-приложения в публичные документы.
- Не считайте зелёный статус синхронизации доказательством, пока не пройдёт тест реальной записи и повторной загрузки.
